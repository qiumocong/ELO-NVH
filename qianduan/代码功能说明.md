# EOL-NVH 检测系统前端 — 代码功能说明

## 一、项目概述

本项目包含两个可视化工具：

**工具 1：检测系统（main.py）**
- 实时显示 4 组传感器数据（X/Y/Z 振动 + 电流）的时域曲线
- 对 X/Y/Z 振动数据做傅里叶变换（FFT），显示频谱图
- 选择检测模型、显示工件编号、展示自动检测结果

**工具 2：数据集标注工具（labeler.py）**
- 实时显示同样的时域曲线和频谱图
- 人工观察图表，手动判断数据合格/不合格
- 标签发送给后端保存，用于制作训练数据集

**技术栈：** Python + PyQt5（界面）+ pyqtgraph（实时图表）+ numpy（FFT 计算）

## 四、各文件功能详解

### 4.1 `main.py` — 程序入口

**作用：** 启动整个应用程序。

**做了什么：**
1. 创建 PyQt5 应用实例
2. 设置全局字体（微软雅黑）
3. 创建主窗口
4. 根据命令行参数选择数据源：
   - 默认：`MockDataSource`（模拟数据，开发调试用）
   - `--ws` 参数：`WebSocketClient`（连接真实后端）
5. 把数据源和窗口连接起来（信号绑定）
6. 启动数据源，显示窗口

**启动方式：**
```bash
conda activate task
python main.py          # 用模拟数据
python main.py --ws     # 用真实 WebSocket
```

---

### 4.2 `config.py` — 配置文件

**作用：** 集中管理所有可调参数，方便修改。

**包含的配置：**

| 配置项 | 默认值 | 含义 |
|--------|--------|------|
| `WS_URL` | `ws://localhost:8080` | WebSocket 服务器地址 |
| `RECONNECT_INTERVAL` | 3 | 断线后多久重连（秒） |
| `MAX_POINTS` | 5000 | 每条曲线最多保留多少个点 |
| `FFT_WINDOW_SIZE` | 1024 | FFT 计算用多少个数据点 |
| `SAMPLE_RATE` | 1000 | 采样频率（每秒采多少个点） |
| `CHART_REFRESH_INTERVAL` | 50 | 图表刷新间隔（毫秒） |
| `CHANNELS` | `["x", "y", "z", "current"]` | 所有数据通道名称 |
| `VIBRATION_CHANNELS` | `["x", "y", "z"]` | 需要做 FFT 的通道 |

---

### 4.3 `mock_data.py` — 模拟数据源

**作用：** 模拟后端行为，开发阶段不需要真实后端就能调试界面。

**模拟的流程：**
1. `start()` → 报告"已连接"，发送模型列表，但**不推送数据**
2. 用户选择模型 → `send_model()` → 返回工件 ID，**开始推送数据**
3. 推送 10 秒后 → 自动返回检测结果

**生成的数据：**
- X 方向：50Hz 正弦波 + 噪声（模拟振动）
- Y 方向：120Hz 正弦波 + 噪声
- Z 方向：80Hz 正弦波 + 噪声
- 电流：缓慢漂移 + 噪声

---

### 4.4 `websocket_client.py` — WebSocket 客户端

**作用：** 连接真实后端服务器，接收和发送消息。

**工作原理：**
- 在**独立线程**中运行 WebSocket 连接（避免阻塞界面）
- 通过 **Qt 信号**（pyqtSignal）把数据传给主线程更新界面
- 断线后自动重连

**发送的消息：**
- `send_model(model_id)` → 告诉后端选择了哪个模型
- `send_start()` → 开始检测
- `send_stop()` → 停止检测

**接收的消息类型：**
- `data` / `data_batch` → 传感器数据
- `result` → 检测结果
- `obj_id` → 工件编号
- `model_list` → 可用模型列表

---

### 4.5 `fft_utils.py` — FFT 计算工具

**作用：** 把时域数据（振动波形）转换成频域数据（频率-幅值谱）。

**什么是 FFT？**
- 时域数据：传感器每秒采集 1000 个点，画出来是波形
- FFT（快速傅里叶变换）：分析这个波形里包含哪些频率成分
- 频谱图：横轴是频率（Hz），纵轴是幅值，能看出振动的主要频率

**两个函数：**
- `compute_fft(data)` → 前端自己算 FFT（默认方式）
- `compute_fft_from_backend(freqs, magnitudes)` → 直接用后端算好的频谱数据

---

### 4.6 `ui/main_window.py` — 主窗口

**作用：** 把所有界面组件拼装在一起，处理数据分发。

**布局结构：**
```
┌─────────────────────────────────────────┐
│  HeaderWidget（工件ID + 模型选择）        │
│  StatusBarWidget（连接状态指示灯）        │
├────────────┬────────────────────────────┤
│            │  x时域  y时域  z时域  电流时域 │
│  Result    │                            │
│  Panel     │  x频谱  y频谱  z频谱   (空)  │
│  (检测结果) │                            │
└────────────┴────────────────────────────┘
```

**核心方法 `connect_data_source()`：**
把数据源的信号绑定到各个组件，实现数据流转：
- 数据源发数据 → 时域曲线更新 → 频谱图更新
- 数据源发结果 → 结果面板更新
- 数据源发 obj_id → 顶部 ID 更新

---

### 4.7 `ui/header_widget.py` — 顶部栏

**作用：** 显示工件 ID 和模型选择下拉框。

**包含的控件：**
- `QLabel`：显示 "工件 ID: OBJ_xxx"
- `QComboBox`：模型选择下拉框
- `QPushButton`："确认"按钮

**用户操作：** 从下拉框选模型 → 点确认 → 触发 `model_selected` 信号

---

### 4.8 `ui/status_bar.py` — 状态栏

**作用：** 显示 WebSocket 连接状态和检测状态。

**显示内容：**
- 绿色圆点 + "已连接" / 灰色圆点 + "未连接"
- "检测状态: 待检测 / 检测中 / 完成"

---

### 4.9 `ui/time_chart.py` — 时域曲线图

**作用：** 显示单个通道的实时时域曲线。

**工作原理：**
1. 用 `collections.deque` 存数据（固定最大长度，自动丢弃旧数据）
2. 接收新数据后追加到 deque
3. 调用 pyqtgraph 的 `setData()` 更新曲线

**4 个实例：** X 振动（红）、Y 振动（绿）、Z 振动（蓝）、电流（橙）

---

### 4.10 `ui/spectrum_chart.py` — 频谱图

**作用：** 显示 FFT 变换后的频谱。

**工作原理：**
1. 接收时域数据
2. 取最近 1024 个点
3. 调用 `fft_utils.compute_fft()` 计算频谱
4. 用 pyqtgraph 画出频率-幅值曲线

**3 个实例：** X 频谱（红）、Y 频谱（绿）、Z 频谱（蓝）

---

### 4.11 `ui/result_panel.py` — 检测结果面板

**作用：** 显示最终检测结果。

**显示状态：**
- 灰色 "待检测" → 初始状态
- 绿色 "合格" + 置信度 → 检测通过
- 红色 "不合格" → 检测不通过
- 橙色 "异常" → 其他情况

## 六、如何切换到真实后端

目前用的是模拟数据。接上真实后端后：

1. 确保后端 WebSocket 服务运行在 `ws://localhost:8080`
2. 用 `python main.py --ws` 启动
3. 后端需要按以下格式发送消息：

**数据消息：**
```json
{
  "type": "data_batch",
  "obj_id": "OBJ202601010001",
  "time": [0.001, 0.002, 0.003],
  "x": [0.12, 0.15, 0.11],
  "y": [0.05, 0.07, 0.04],
  "z": [0.20, 0.19, 0.21],
  "current": [1.20, 1.25, 1.22]
}
```

**结果消息：**
```json
{
  "type": "result",
  "obj_id": "OBJ202601010001",
  "result": "OK",
  "score": 0.96,
  "message": "检测合格"
}
```

## 八、数据集标注工具

### 8.1 启动方式

```bash
conda activate task
python labeler.py          # 用模拟数据
python labeler.py --ws     # 用真实 WebSocket
```

### 8.2 和检测系统的区别

| 项目 | 检测系统 (main.py) | 标注工具 (labeler.py) |
|------|-------------------|---------------------|
| 目的 | 使用模型自动检测 | 人工标注制作数据集 |
| 模型选择 | 需要 | 不需要 |
| 工件 ID | 显示 | 不显示 |
| 结果来源 | 后端自动返回 | 人工点击按钮判断 |
| 数据推送 | 选模型后才开始 | 启动后立即开始 |
| 标签保存 | 不保存 | 发送给后端保存 |

### 8.3 标注流程

```
启动标注工具
    ↓
数据立即开始推送，图表实时显示
    ↓
人工观察 4 个时域曲线 + 3 个频谱图
    ↓
判断数据合格 → 点"合格"按钮（标签=1）
判断数据不合格 → 点"不合格"按钮（标签=0）
    ↓
前端把标签发送给后端
    ↓
后端把当前数据段 + 标签一起保存
    ↓
继续观察下一段数据，重复标注
```

### 8.4 标签发送格式

前端发送给后端的标注消息：

```json
{
  "type": "label",
  "label": 1
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 固定为 `"label"` |
| `label` | int | `1` = 合格，`0` = 不合格 |

### 8.5 标签保存建议（后端负责）

前端只发送标签，**后端负责保存**。建议后端保存格式：

**方案 A：CSV 文件**
```csv
time,x,y,z,current,label
0.001,0.12,0.05,0.20,1.20,1
0.002,0.15,0.07,0.19,1.25,1
...
```

**方案 B：按文件夹分类**
```
dataset/
├── OK/          ← label=1 的数据段
│   ├── 001.csv
│   └── 002.csv
└── NG/          ← label=0 的数据段
    ├── 003.csv
    └── 004.csv
```

## 九、后端对接规范（真实部署必读）

前端通过 WebSocket 与后端通信。后端需要实现以下内容。

### 9.1 连接信息

| 项目 | 说明 |
|------|------|
| 协议 | WebSocket（ws 或 wss） |
| 默认地址 | `ws://localhost:8080`（可在 `config.py` 的 `WS_URL` 修改） |
| 连接方式 | 前端主动连接后端，断线后每 3 秒自动重连 |
| 数据格式 | JSON 文本消息（不是二进制） |

---

### 9.2 后端需要接收的消息（前端 → 后端）

#### ① 选择模型

用户在前端选了模型并点"确认"后，前端发送：

```json
{
  "type": "select_model",
  "model_id": "模型A"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 固定为 `"select_model"` |
| `model_id` | string | 用户选择的模型名称或 ID |

#### ② 开始检测（可选）

如果需要手动触发开始，前端可发送：

```json
{
  "type": "start"
}
```

#### ③ 停止检测（可选）

```json
{
  "type": "stop"
}
```

#### ④ 人工标注（标注工具用）

用户在标注工具中点了"合格"或"不合格"后，前端发送：

```json
{
  "type": "label",
  "label": 1
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 固定为 `"label"` |
| `label` | int | `1` = 合格，`0` = 不合格 |

**后端收到后：** 应把当前正在推送的数据段与该标签一起保存到数据集中。

---

### 9.3 后端需要发送的消息（后端 → 前端）

前端根据消息的 `type` 字段来识别和处理，**所有消息都必须包含 `type` 字段**。

#### ① 模型列表 — 连接后第一时间发送

告诉前端有哪些模型可选。

```json
{
  "type": "model_list",
  "models": ["模型A", "模型B", "模型C"]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 固定为 `"model_list"` |
| `models` | string[] | 可用模型名称列表 |

**发送时机：** 前端连接成功后，后端应立即推送。

---

#### ② 工件 ID — 前端选了模型后发送

告诉前端当前检测的工件编号。

```json
{
  "type": "obj_id",
  "obj_id": "OBJ202601010001"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 固定为 `"obj_id"` |
| `obj_id` | string | 工件编号，显示在前端左上角 |

**发送时机：** 收到前端的 `select_model` 消息后发送。

---

#### ③ 传感器数据 — 持续推送（核心）

检测过程中，后端持续向前端推送传感器数据。

**方式 A：批量推送（推荐，性能更好）**

```json
{
  "type": "data_batch",
  "obj_id": "OBJ202601010001",
  "time": [0.001, 0.002, 0.003, 0.004, 0.005],
  "x": [0.12, 0.15, 0.11, 0.13, 0.14],
  "y": [0.05, 0.07, 0.04, 0.06, 0.05],
  "z": [0.20, 0.19, 0.21, 0.18, 0.22],
  "current": [1.20, 1.25, 1.22, 1.21, 1.23]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 固定为 `"data_batch"` |
| `obj_id` | string | 工件编号（可选，前端不依赖此字段） |
| `time` | number[] | 时间戳数组（秒），长度和其他数组一致 |
| `x` | number[] | X 方向振动数据数组 |
| `y` | number[] | Y 方向振动数据数组 |
| `z` | number[] | Z 方向振动数据数组 |
| `current` | number[] | 电流数据数组 |

**方式 B：单点推送（数据量少时可用）**

```json
{
  "type": "data",
  "timestamp": 0.012,
  "x": 0.21,
  "y": -0.13,
  "z": 0.08,
  "current": 1.25
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 固定为 `"data"` |
| `timestamp` | number | 当前时间戳（秒） |
| `x` | number | X 方向振动值 |
| `y` | number | Y 方向振动值 |
| `z` | number | Z 方向振动值 |
| `current` | number | 电流值 |

**发送时机：** 收到 `select_model` 后开始推送，检测结束停止。

**推送频率建议：**
- 采样率 1000Hz 时，建议每 50ms 推送一批 50 个点（即每秒 20 批）
- 批量大小和推送间隔可在后端调整，前端没有硬性要求

---

#### ④ 检测结果 — 检测完成后发送

```json
{
  "type": "result",
  "obj_id": "OBJ202601010001",
  "result": "OK",
  "score": 0.96,
  "message": "检测合格"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 固定为 `"result"` |
| `obj_id` | string | 否 | 工件编号 |
| `result` | string | 是 | 检测结果，前端识别以下值：`"OK"` / `"PASS"` / `"合格"` → 绿色显示；`"NG"` / `"FAIL"` / `"不合格"` → 红色显示；其他值 → 橙色显示 |
| `score` | number | 否 | 置信度，0~1 之间的小数，前端显示为百分比（如 0.96 → 96.0%）。不传或传 0 则不显示 |
| `message` | string | 否 | 附加说明文字，直接显示在界面上 |

**发送时机：** 检测完成、模型推理结束后发送。

---

### 9.4 完整通信时序

```
前端                              后端
 │                                 │
 │──── WebSocket 连接 ────────────→│
 │                                 │
 │←─── model_list（模型列表）──────│  连接后立即发送
 │                                 │
 │  [用户选择模型，点确认]          │
 │                                 │
 │──── select_model ─────────────→│
 │                                 │
 │←─── obj_id（工件编号）─────────│  收到模型选择后发送
 │                                 │
 │←─── data_batch（传感器数据）────│  开始持续推送
 │←─── data_batch ────────────────│
 │←─── data_batch ────────────────│
 │←─── ...（持续推送）────────────│
 │                                 │
 │←─── result（检测结果）──────────│  检测完成后发送
 │                                 │
```

### 9.5 关于频谱数据（FFT）的两种方案

前端默认自己做 FFT 计算，但也可以接收后端算好的频谱数据。

**方案 A：前端计算（当前默认）**

后端只推送原始时域数据（`x`/`y`/`z`），前端取最近 1024 个点自己做 FFT。

- 优点：后端简单，只发原始数据
- 缺点：前端 CPU 占用稍高

**方案 B：后端计算**

后端在 `data_batch` 消息中额外附带频谱数据，前端直接画图，不做计算：

```json
{
  "type": "data_batch",
  "time": [0.001, 0.002, ...],
  "x": [0.12, 0.15, ...],
  "y": [0.05, 0.07, ...],
  "z": [0.20, 0.19, ...],
  "current": [1.20, 1.25, ...],
  "spectrum": {
    "x": {"freqs": [0, 1, 2, ...], "magnitudes": [0.5, 0.3, ...]},
    "y": {"freqs": [0, 1, 2, ...], "magnitudes": [0.4, 0.2, ...]},
    "z": {"freqs": [0, 1, 2, ...], "magnitudes": [0.6, 0.1, ...]}
  }
}
```

- 优点：前端 CPU 占用低
- 缺点：后端需要额外计算 FFT

> 当前前端代码只实现了方案 A。如果要用方案 B，需要在 `main_window.py` 的 `_on_data()` 中增加对 `spectrum` 字段的解析，调用 `SpectrumChart.update_from_backend()` 即可。

### 9.6 后端需要确认的参数清单

对接前请和后端确认以下参数：

| 序号 | 问题 | 说明 |
|------|------|------|
| 1 | WebSocket 地址 | 默认 `ws://localhost:8080`，实际部署时可能不同 |
| 2 | 采样频率 | 默认 1000Hz，需要和传感器实际采样率一致 |
| 3 | 数据推送方式 | 批量（`data_batch`）还是单点（`data`） |
| 4 | 批量大小 | 每批推多少个点，建议 50~100 |
| 5 | 推送间隔 | 多久推一批，建议 50~100ms |
| 6 | 时间戳格式 | 秒（如 0.001）还是毫秒（如 1）或其他 |
| 7 | FFT 计算方 | 前端算还是后端算 |
| 8 | 模型列表来源 | 后端推送还是前端写死 |
| 9 | 检测结果格式 | `OK/NG`、`pass/fail`、`合格/不合格` 或其他 |
| 10 | 连接是否需要认证 | 是否需要 token 或其他鉴权 |
