# EOL-NVH 检测系统前端任务理解说明

## 1. 项目背景

当前项目需要基于检测数据训练模型，并在检测过程中通过前端界面实时展示检测数据、频谱分析结果和最终检测结果。

你负责的部分主要是 **前端界面开发**，不是模型训练本身。前端的核心作用是：

- 提供模型选择入口；
- 展示当前检测工件的编号 `obj_id`；
- 实时接收并显示后端传来的检测数据；
- 对 `x / y / z` 三组振动数据生成或展示傅里叶变换后的频谱图；
- 展示后端返回的最终检测结果。

可以理解为：**你负责做一个实时检测可视化前端，把后端数据、模型选择、图表展示和检测结果串起来。**

---

## 2. 页面主要功能

前端界面可以参考现有图片中的工业检测系统界面，整体上包括以下几个区域。

### 2.1 工件信息区

页面左上角或顶部区域显示当前正在检测的工件编号：

```text
工件 ID：OBJ_xxx
```

其中 `obj_id` 由后端提供，前端只负责显示。

旁边可以放一个“选择模型”的按钮或下拉框：

```text
当前模型：模型A
[选择模型]
```

用户选择模型后，前端需要把选择的模型 ID 或模型名称发送给后端。

---

### 2.2 实时数据展示区

前端会接收到 4 组随时间变化的数据：

```text
x 方向振动数据
y 方向振动数据
z 方向振动数据
电流数据
```

这 4 组数据的横坐标都是时间，因此前端需要动态绘制 4 张时域曲线图：

```text
x - time
y - time
z - time
current - time
```

这些图表需要实时更新，随着后端持续推送数据，曲线不断向前滚动。

---

### 2.3 频谱图展示区

对于 `x / y / z` 三组振动数据，需要生成它们经过傅里叶变换后的频谱图。

也就是从时域数据：

```text
x(t), y(t), z(t)
```

转换为频域数据：

```text
X(f), Y(f), Z(f)
```

频谱图的横坐标通常是频率，纵坐标是幅值：

```text
Frequency (Hz) - Amplitude
```

这里需要和后端或算法同事确认：**FFT 是前端计算，还是后端计算后直接传给前端。**

如果由前端计算，前端需要知道：

- 采样频率 `fs`；
- FFT 窗口长度 `N`；
- 是否需要加窗，例如 Hann 窗；
- 频谱刷新频率；
- 显示单边谱还是双边谱。

如果由后端计算，前端只需要接收频谱数据并绘图。

---

### 2.4 检测结果展示区

左下角或侧边栏显示检测结果，例如：

```text
检测状态：检测中
检测结果：合格 / 不合格 / 异常
```

最终检测结果由后端提供，前端不负责判断好坏，只负责展示。

可能的结果数据格式类似：

```json
{
  "type": "result",
  "obj_id": "OBJ202601010001",
  "result": "OK",
  "score": 0.96,
  "message": "检测合格"
}
```

## 3. 前后端数据流理解

整体流程可以理解为：

```text
用户选择模型
      ↓
前端把 model_id 发送给后端
      ↓
后端确认模型并准备检测
      ↓
后端返回当前工件 obj_id
      ↓
后端持续推送 x / y / z / current 数据
      ↓
前端实时绘制时域曲线
      ↓
前端生成或展示 x / y / z 频谱图
      ↓
后端返回最终检测结果
      ↓
前端展示合格 / 不合格 / 异常
```

你的任务重点是把这个流程做成稳定、清晰、可交互的前端页面。

---

## 4. 前端负责的内容

前端主要负责以下内容：

1. 页面整体布局；
2. 工件 ID 显示；
3. 模型选择按钮或下拉框；
4. 把用户选择的模型发送给后端；
5. 接收后端实时推送的检测数据；
6. 动态绘制 `x / y / z / current` 四组时域曲线；
7. 对 `x / y / z` 数据生成或展示频谱图；
8. 显示检测状态，例如待检测、检测中、完成、异常；
9. 显示后端返回的最终检测结果；
10. 处理连接状态、断线重连、数据清空、异常提示等交互逻辑。

---

## 5. 后端负责的内容

后端主要负责以下内容：

1. 提供模型列表；
2. 接收前端选择的模型；
3. 提供当前工件编号 `obj_id`；
4. 持续推送检测数据；
5. 可能负责模型推理；
6. 返回最终检测结果；
7. 根据项目分工，可能负责 FFT 计算。

前端不需要负责模型训练和最终判定逻辑，除非团队明确要求部分逻辑放在前端。

---

## 6. 推荐通信方式

因为需要实时动态显示数据，推荐使用 **WebSocket** 作为前后端通信方式。

后端可以按单点或批量方式推送数据。

### 6.1 单点数据格式示例

```json
{
  "type": "data",
  "obj_id": "OBJ202601010001",
  "timestamp": 0.012,
  "x": 0.21,
  "y": -0.13,
  "z": 0.08,
  "current": 1.25
}
```

### 6.2 批量数据格式示例

```json
{
  "type": "data_batch",
  "obj_id": "OBJ202601010001",
  "time": [0.001, 0.002, 0.003],
  "x": [0.12, 0.15, 0.11],
  "y": [0.05, 0.07, 0.04],
  "z": [0.20, 0.19, 0.21],
  "current": [1.20, 1.25, 1.22]
}
```

如果数据采样频率较高，建议后端按批量方式推送，前端按固定刷新频率更新图表，这样性能更稳定。

---

## 7. 图表实现建议

前端动态图表可以使用：

- ECharts；
- AntV G2；
- Plotly；
- Chart.js。

工业检测界面中比较推荐 **ECharts**，原因是：

- 支持实时折线图；
- 支持多图联动；
- 性能较好；
- 配置灵活；
- 适合做工业风格的数据看板。

需要注意的是，前端不要无限保存所有历史数据。建议采用滑动窗口，例如：

```text
只显示最近 10 秒数据
```

或者限制最大点数：

```text
每条曲线最多保存 5000 或 10000 个点
```

这样可以避免长时间运行后页面卡顿。

---

## 8. FFT 频谱图实现建议

如果 FFT 在前端做，可以采用以下思路：

```text
每隔固定时间，例如 500ms 或 1s，
取最近一段 x / y / z 数据，
分别进行 FFT，
然后更新对应频谱图。
```

基本频率坐标计算公式为：

```text
frequency = k * fs / N
```

其中：

```text
fs：采样频率
N：FFT 点数
k：频率点索引
```

需要和算法或后端确认：

- 采样频率是多少；
- 每次 FFT 使用多少个点；
- 是否需要滤波；
- 是否需要加窗；
- 频谱纵坐标展示幅值、能量还是分贝；
- 频谱图是否需要实时刷新；
- 是否需要保存频谱历史。

## 10. 需要和后端确认的问题

正式开发前，建议优先和后端、算法同事确认以下问题：

1. 数据通过 WebSocket 推送，还是 HTTP 轮询？
2. 后端每次推送单点数据，还是批量数据？
3. 4 组数据的字段名分别是什么？
4. 时间戳由后端提供，还是前端自己生成？
5. `x / y / z / current` 的采样频率是多少？
6. FFT 是前端计算，还是后端计算后返回？
7. 如果前端做 FFT，窗口长度 `N` 取多少？
8. 是否需要对数据做滤波或加窗？
9. 模型列表由后端返回，还是前端写死？
10. 用户选择模型后，是否还需要点击“开始检测”？
11. `obj_id` 是检测开始前返回，还是检测过程中返回？
12. 检测结果的格式是什么，例如 `OK / NG`、`pass / fail`，还是中文？
13. 检测过程中是否有状态，例如待检测、检测中、完成、异常？
14. 一次检测结束后，前端是否需要保存历史曲线？
15. 数据量较大时，前端是否只显示最近一段时间？
16. 断线后是否需要自动重连？
17. 多个工件连续检测时，前端是否需要自动清空上一件数据？

## 11. 任务边界总结

你可以向团队这样描述你的任务：

> 我负责开发检测系统的前端界面。前端需要支持模型选择，显示当前工件 `obj_id`，实时接收后端推送的 `x / y / z` 振动数据和电流数据，并动态绘制时域曲线。同时，针对 `x / y / z` 数据生成或展示傅里叶变换后的频谱图。检测结果由后端返回，前端负责在界面中展示合格、不合格或异常状态。前端不负责模型训练和最终判定逻辑，只负责交互、数据展示和可视化。

---

## 12. 当前理解结论

你目前的理解基本是正确的：

```text
模型选择：前端人工点击选择
4 组数据：后端提供
obj_id：后端提供
检测结果：后端提供
实时曲线：前端展示
频谱图：前端生成或展示
模型训练：不是前端负责
最终判定：后端或算法模型负责
```

下一步最关键的是：**先和后端确认数据协议，再开始写页面和图表逻辑。**
